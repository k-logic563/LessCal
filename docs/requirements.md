# Googleカレンダー表示プリセット拡張機能 要件定義

## 1. 背景

現在、Googleカレンダーでは社内メンバー全体の予定を確認している。

一方、サポート部ではサポート部メンバーのみの予定や対応状況を確認する必要があり、Googleカレンダーとは別にスプレッドシートも利用している。

Googleカレンダーでは対象メンバーのみをチェックして表示することは可能だが、毎回複数メンバーの表示・非表示を切り替える必要があり、操作に手間がかかる。

また、Googleカレンダー自体の情報量が多いため、新しい操作UIをGoogleカレンダー画面内へ追加すると、視認性を下げる可能性がある。

---

## 2. 目的

Googleカレンダー上で表示しているメンバーの組み合わせを「プリセット」として保存し、Chrome拡張機能からワンクリックで切り替えられるようにする。

特に以下を重視する。

* 誰でも簡単に操作できる
* 導入コストが低い
* 運用コストがかからない
* Googleカレンダーの既存運用を大きく変更しない
* 説明を読まなくても基本操作が理解できる

---

## 3. 基本方針

### Googleカレンダー

予定の登録・確認を行う既存の場所としてそのまま利用する。

### Chrome拡張機能

表示するメンバーの組み合わせを切り替えるための操作画面として利用する。

### UI

Googleカレンダー本体へのUI追加は原則行わない。

Chrome拡張機能のアイコンをクリックした際に表示されるPopup内で操作を完結させる。

---

## 4. 想定利用フロー

### 初回設定

1. Googleカレンダーへ必要なメンバーのカレンダーを追加する
2. プリセットに含めたいメンバーのみ表示する
3. Chrome拡張機能を開く
4. 「現在の表示を保存」を押す
5. プリセット名を入力する
6. 保存する

例：

```text
サポート部
```

として保存する。

### 通常利用

1. Googleカレンダーを開く
2. Chrome拡張機能を開く
3. 使用したいプリセットをクリックする
4. 保存済みのメンバー構成へ表示が切り替わる

---

## 5. プリセット適用ルール

プリセットを選択した場合、表示状態は以下のルールで切り替える。

* プリセットに含まれるメンバーをONにする
* プリセットに含まれないメンバーをOFFにする
* 自分自身のカレンダーは常時ONにする
* 自分自身はプリセットの保存内容に依存しない

例：

```text
プリセット：サポート部

自分      → ON
田中      → ON
佐藤      → ON
山田      → ON
鈴木      → OFF
高橋      → OFF
```

---

## 6. MVP機能

### 6.1 プリセット一覧表示

保存済みのプリセットをPopup内に一覧表示する。

例：

```text
サポート部
開発部
リーダー
自分のチーム
```

部署という概念はシステム側では持たない。

ユーザーが自由な名称でプリセットを作成できるものとする。

---

### 6.2 プリセット切り替え

プリセット名をクリックすると、保存されているメンバー構成へGoogleカレンダーの表示状態を切り替える。

切り替え時は、対象外メンバーをOFFにする。

自分自身のカレンダーは常時ONとする。

---

### 6.3 現在の表示状態を保存

Googleカレンダーで現在表示されているメンバー構成を取得し、新しいプリセットとして保存する。

保存時にユーザーが入力する情報は原則としてプリセット名のみとする。

---

### 6.4 プリセット編集

各プリセット右側に `⋯` メニューを表示する。

メニューから以下を操作できる。

* 名前を変更
* 現在の表示状態で更新
* 削除

専用のプリセット管理画面は設けない。

---

### 6.5 現在選択中のプリセット表示

Googleカレンダーの現在の表示状態とプリセット内容が一致している場合、そのプリセットを選択中として表示する。

例：

```text
● サポート部
```

プリセット適用後にユーザーがGoogleカレンダー上で手動変更した場合は、プリセット未一致状態として扱う。

例：

```text
現在：カスタム
```

---

## 7. UIイメージ

Popupはできるだけ簡潔にする。

```text
表示プリセット

● サポート部              ⋯
  開発部                  ⋯
  リーダー                ⋯

────────────────

＋ 現在の表示を保存
```

### UI設計原則

* Googleカレンダー画面を汚さない
* Popup内で操作を完結させる
* プリセット名をクリックすると即時切り替える
* 編集操作は `⋯` に集約する
* 設定画面へ何階層も移動させない
* 機能数より分かりやすさを優先する
* 操作回数を可能な限り少なくする

## 8. 技術構成

以下を基本構成とする。

* WXT
* Vue 3
* TypeScript
* Chrome Extension
* Chrome Storage API
* Content Script
* Chrome Messaging

プロトタイプでは以下を使用しない。

* 独自バックエンド
* 独自DB
* 外部サーバー
* Google Calendar API
* Google Workspace Directory API
* OAuth認証

---

## 9. システム構成案

```text
Chrome Extension Popup
        ↓
Chrome Messaging
        ↓
Content Script
        ↓
Calendar Adapter
        ↓
Google Calendar DOM
```

プリセット情報はChrome Storageへ保存する。

```text
Popup
  ↓
Preset Service
  ↓
Chrome Storage
```

GoogleカレンダーのDOM操作は `Calendar Adapter` 相当の責務へ分離する。

---

## 10. データ構造案

```ts
type CalendarPreset = {
  id: string;
  name: string;
  calendarIds: string[];
  createdAt: number;
  updatedAt: number;
};
```

プリセットには、可能であれば表示名ではなくカレンダーを一意に識別できる情報を保存する。

自分自身のカレンダーは常時ONとするため、原則としてプリセットの `calendarIds` には含めない。

---

## 11. 前提・制約

プリセットへ登録できる対象は、Googleカレンダー上へ追加済みのカレンダーとする。

そのため、初回のみ対象メンバーをGoogleカレンダーへ追加する必要がある。

初期設定に多少の手動作業が発生しても、日常的な表示切り替え作業を大幅に減らせることを優先する。

---

## 12. 主な懸念点

### GoogleカレンダーのDOM変更

Googleカレンダーの画面構造が変更された場合、表示状態の取得・切り替え処理が動作しなくなる可能性がある。

そのためDOM操作部分を他のロジックから分離する。

### カレンダー識別方法

表示名だけでカレンダーを識別すると、同姓同名などで問題になる可能性がある。

実装時にGoogleカレンダーのDOMを調査し、安定して利用できる一意な識別情報が存在するか確認する。

### 保存データ

初期段階では個人単位の利用を想定する。

プリセット共有や管理者による一括配布は対象外とする。

---

## 13. プロトタイプで実装しない機能

以下は初期MVPの対象外とする。

* プリセット共有
* 部署マスター
* 管理者機能
* ユーザー管理
* 部署メンバー自動取得
* Google Workspace連携
* 30分刻みのサポート対応表
* スプレッドシート連携
* 複数端末間の独自同期機能

---

## 14. 成功条件

MVPでは以下を満たせれば成功とする。

1. 現在表示中のメンバー構成をプリセットとして保存できる
2. 保存したプリセットをワンクリックで呼び出せる
3. プリセットに含まれないメンバーをOFFにできる
4. 自分自身のカレンダーは常時ONになる
5. プリセットの名前変更・更新・削除ができる
6. Googleカレンダー本体へ追加UIを表示しない
7. サーバーや有料サービスなしで動作する
8. 利用者が説明なしでも基本操作を理解できる

---

## 15. 開発フェーズ

### Phase 0

Chrome拡張として起動できる最小構成を作成する。

実装対象：

* WXT
* Vue 3
* TypeScript
* Popup
* 必要な依存関係
* npm scripts
* 開発起動
* ビルド
* Chromeへの読み込み確認

機能実装は行わない。

Phase 0では、`npm install` 後にすぐ以下を実行できる状態を目指す。

```bash
npm run dev
```

```bash
npm run build
```

実装後は以下を明示する。

* 開発起動に使用するコマンド
* ビルドに使用するコマンド
* Chromeで「パッケージ化されていない拡張機能」として読み込む対象ディレクトリ

### Phase 1

Popupの基本UIを作成する。

### Phase 2

Googleカレンダー上のカレンダー一覧と表示状態を取得する。

### Phase 3

現在の表示状態をプリセットとして保存する。

### Phase 4

プリセットを適用し、表示メンバーを切り替える。

### Phase 5

プリセットの名前変更・更新・削除を実装する。

### Phase 6

選択中プリセットおよびカスタム状態を判定する。
